# 解题大纲 JSON 格式规范

## 顶层结构

```json
{
  "id": "Q002_part3",
  "outline": [
    { "step": 1, "title": "审题", "content": "..." }
  ],
  "keyKnowledge": [
    { "name": "阿氏圆", "description": "..." }
  ]
}
```

## 字段说明

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `id` | string | 是 | 题目编号；无编号时用 `question_outline_001` |
| `outline` | array | 是 | 解题步骤数组 |
| `outline[].step` | number | 是 | 从 1 开始连续编号 |
| `outline[].title` | string | 是 | 简短步骤标题，如「审题」「构造辅助点 D」 |
| `outline[].content` | string | 是 | 本步核心条件/计算/推理，一句话写清 |
| `keyKnowledge` | array | 是 | 关键知识点数组 |
| `keyKnowledge[].name` | string | 是 | 知识点名称 |
| `keyKnowledge[].description` | string | 是 | 该知识点在本题中的作用 |

## 步骤设计建议

常见步骤标题：

- 审题
- 提取条件
- 建立坐标/表达式
- 提取公因子
- 构造辅助点/辅助线
- 计算已知量
- 证明比值关系
- 证明相似/全等
- 线段替换
- 转化最值
- 求最小值
- 得出结论

## 内容压缩原则

- 一步只做一件事。
- 保留关键等式，不保留冗余口算。
- 图中对象必须文字化：点坐标、圆心半径、交点、动点范围、目标式。
- 若有最值问题，必须写清「何时取等号」。

## 禁止

- 不要输出互动教案字段：`题目`、`步骤一`、`问题`、`答案`、`错误提示`。
- 不要逐字 OCR 题解；要归纳成步骤。
- 不要输出 `relatedSteps` 字段。
- 不要漏掉最终结论。
